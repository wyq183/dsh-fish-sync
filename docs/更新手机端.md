> **这份文档是给「新开的会话」看的。** 照着做，不用重新摸索。
> 最后更新：2026-10-23 · 大肥鱼（补了 4 个新坑：WebView 看不见、force-stop 不起引擎、无线序列号、验证看新字段）

## 零、先搞清楚三个位置

| 是什么 | 在哪 |
|:---|:---|
| **源码（唯一真相）** | `C:\Users\you\.dsh\projects\dsh-fish-sync\` |
| **电脑端部署** | `C:\Users\you\.dsh\profiles\desktop\node_modules\@dsh-external\dsh-fish-sync\` |
| **手机端暂存区** | `/sdcard/DeepSeekHarness/fish-sync/`（adb 可写） |
| **手机端实际位置** | `/data/user/0/com.deepseek.harness/files/payload/dshhome/profiles/web/node_modules/@dsh-external/dsh-fish-sync/`（**adb 写不进去**） |

**改代码的顺序永远是：改源码 → 测 → 部署电脑端 → 推手机。**

---

## 一、为什么手机端不能直接 `adb push`

Android 的 App 私有目录 `/data/user/0/...` **shell 用户没有权限**。
`adb push` 会报 `Permission denied`。

**唯一能写进去的身份是 App 自己。** 办法是走 App 的「主控台」。

---

## 二、主控台是什么（关键机制）

手机 App 启动时会读这个文件：

```
/sdcard/DeepSeekHarness/console/console.json
```

里面可以定义一批「自定义按钮」，每个按钮对应一条 shell 命令，
**以 App 身份执行**（所以能写私有目录）。

格式：

```json
{
  "schema": 1,
  "name": "按钮组名字",
  "layout": { "style": "classic", "order": ["actions"] },
  "actions": [
    {
      "id": "唯一id",
      "icon": "",
      "type": "shell",
      "label": "按钮上显示的字",
      "cmd": "要执行的命令",
      "confirm": true,
      "continueOnError": true
    }
  ]
}
```

⚠️ **改完 console.json 要重启 App 才生效**（或者重新进主控台）。

⚠️ **这个文件是「临时工具位」，用完要还原。** 原文件备份在
`console.json.bak`（我每次都会先备份再覆盖）。

```powershell
cd C:\Users\you\.dsh\projects\dsh-fish-sync

# 语法
foreach($f in @("lib\identity.js","lib\manifest.js","lib\server.js","lib\sync.js","lib\discovery.js","lib\pairing.js","lib\http.js","lib\index.js","lib\client.js","lib\cli.js")){

# 自检（必须全绿才往下走）
node test\offline.mjs
node test\load.mjs
node test\pairing.mjs
node test\discovery.mjs
node test\client.mjs
node test\http.mjs
```

### 步骤 2：部署到电脑端

```powershell
$src="C:\Users\you\.dsh\projects\dsh-fish-sync"
$dst="C:\Users\you\.dsh\profiles\desktop\node_modules\@dsh-external\dsh-fish-sync"
Copy-Item -LiteralPath "$src\lib\index.js" -Destination "$dst\lib\index.js" -Force
# ... 其他改过的文件同理
```

⚠️ **用 `-LiteralPath`**，路径里有中文/特殊字符时普通 `-Destination` 会静默失败（我踩过，命令返回空、文件没更新）。

### 步骤 3：推到手机暂存区

```powershell
$env:MSYS_NO_PATHCONV=1
$S = "10AE5P278U000RZ"   # ← USB 序列号，见下方「设备选择」
& adb -s $S push "$src\lib\." /sdcard/DeepSeekHarness/fish-sync/lib/
& adb -s $S push "$src\test\." /sdcard/DeepSeekHarness/fish-sync/test/
```

### 步骤 4：写一个拷贝脚本（纯 ASCII！）

**必须用 ASCII 写**，中文在 App 身份执行时会乱码。

```powershell
$env:MSYS_NO_PATHCONV=1
$s = @'
P=/data/user/0/com.deepseek.harness/files/payload/dshhome/profiles/web
SRC=/sdcard/DeepSeekHarness/fish-sync
DST=$P/node_modules/@dsh-external/dsh-fish-sync
OUT=/sdcard/DeepSeekHarness/tmp/upd.txt
{
  cp "$SRC/lib/"*.js "$DST/lib/"
  cp "$SRC/test/"*.mjs "$DST/test/"
  echo "=== copied ==="
  ls -l "$DST/lib/index.js"
} > "$OUT" 2>&1
echo done
'@
$s | Out-File "$env:USERPROFILE\.dsh\scratch\upd.sh" -Encoding ASCII -NoNewline
& adb -s $S push "$env:USERPROFILE\.dsh\scratch\upd.sh" /sdcard/DeepSeekHarness/tmp/upd.sh
```

### 步骤 5：改 console.json，加一个按钮

```powershell

$S = "10AE5P278U000RZ"

# 先备份！

$console = @'

  "actions":[{"id":"u","icon":"","type":"shell","label":"Upd","cmd":"sh /sdcard/DeepSeekHarness/tmp/upd.sh; cat /sdcard/DeepSeekHarness/tmp/upd.txt","confirm":true,"continueOnError":true}]}

```

### 步骤 6：在手机上点按钮

**⚠️ 不要盲点坐标。** 必须先 dump 出真实位置：

```powershell
$env:MSYS_NO_PATHCONV=1
$S = "10AE5P278U000RZ"

# 1. 先回主界面（如果不在）
& adb -s $S shell "am start -n com.deepseek.harness/.MainActivity"
Start-Sleep -Seconds 3

# 2. dump 当前界面
& adb -s $S shell "uiautomator dump /sdcard/DeepSeekHarness/tmp/x.xml"
& adb -s $S pull /sdcard/DeepSeekHarness/tmp/x.xml "$env:USERPROFILE\.dsh\scratch\x.xml"

# 3. 读出按钮真实坐标
$xml = [System.IO.File]::ReadAllText("$env:USERPROFILE\.dsh\scratch\x.xml")
# 确认在控制台
if($xml -notmatch 'DEEPSEEK HARNESS'){ Write-Output "⚠ 不在控制台，别点！" }
$m = [regex]::Matches($xml, 'text="([^"]*)"[^>]*bounds="\[(\d+),(\d+)\]\[(\d+),(\d+)\]"')
foreach($x in $m){
  if($x.Groups[1].Value -match '^Upd$'){
    $cx=([int]$x.Groups[2].Value+[int]$x.Groups[4].Value)/2
    $cy=([int]$x.Groups[3].Value+[int]$x.Groups[5].Value)/2
    Write-Output "Upd ($cx,$cy)"
    & adb -s $S shell "input tap $cx $cy"
  }
}
```

#### 🔴 上面这段 `uiautomator dump` **对主控台无效**（2026-10-23 踩到）

**主控台是 WebView 应用，uiautomator 只看到一整个 `<WebView>` 节点，里面一个文字都没有。**

实测 dump 出来的 XML 只有 2273 字节，全是 `FrameLayout > LinearLayout > WebView`，
**连按钮标签都读不到** → 上面那段按 `text="Upd"` 找坐标的代码**一个都匹配不上，静默什么都不做**。

**必须改成截图 + 自己看图定位：**

```powershell
$env:MSYS_NO_PATHCONV=1
$S = "adb-10AE5P278U000RZ-w6VG2F._adb-tls-connect._tcp"

# 1. 截图
& adb -s $S shell "screencap -p /sdcard/DeepSeekHarness/tmp/s.png"
& adb -s $S pull /sdcard/DeepSeekHarness/tmp/s.png "$env:USERPROFILE\.dsh\scratch\s.png"

# 2. 用 read_image 看这张图，找到按钮在哪
```

**定位坐标的正确做法（我点偏了三次才学会）：**

1. 先看整张截图，找到按钮大概在哪个区域
2. **裁一块小区域放大看**，在裁剪图里量出按钮中心
3. 换算回原图：`原图 y = 裁剪起点 y + 裁剪图里的 y`

```powershell
Add-Type -AssemblyName System.Drawing
$src = [System.Drawing.Image]::FromFile("$scratch\s.png")
$crop = New-Object System.Drawing.Bitmap(1080, 260)
$g = [System.Drawing.Graphics]::FromImage($crop)
# 参数：目标矩形(0,0,1080,260)，源矩形(0, 裁剪起点y, 1080, 260)
$g.DrawImage($src, (New-Object System.Drawing.Rectangle(0,0,1080,260)),
                   (New-Object System.Drawing.Rectangle(0,1150,1080,260)),
                   [System.Drawing.GraphicsUnit]::Pixel)
$g.Dispose()
$crop.Save("$scratch\crop.png", [System.Drawing.Imaging.ImageFormat]::Png)
$crop.Dispose(); $src.Dispose()
```

**为什么不能凭整图估：** 1080×2400 的截图缩到 560 宽给我看时，
一个按钮只剩几十像素高，估出来的 y 能差 100+ 像素 —— **足够点到隔壁按钮上**。
我 2026-10-23 就点到了「重新解压」（那一带是危险按钮）。

**点之前必做**：确认「我要点的那个按钮，在屏幕上到底是哪一行字」。
截图里读一遍，跟预期对上再点。

**参考坐标（1080×2400，1.20.0 版本，2026-10-23 实测）**：

| 目标 | 坐标 | 备注 |
|:---|:---|:---|
| `Upd` 自定义按钮 | `(300, 510)` | 红框，在「自定义按钮」卡片里 |
| 确认框「执行」 | `(810, 1525)` | 点完按钮后弹出 |
| 「启动引擎」 | `(310, 1240)` | force-stop 之后必点，见坑 7 |
| 「重启」 | `(710, 1240)` | 引擎在跑时用这个 |

点完会弹确认框，再 dump 一次找「执行」按钮：

```powershell
Start-Sleep -Seconds 2
& adb -s $S shell "uiautomator dump /sdcard/DeepSeekHarness/tmp/y.xml"
& adb -s $S pull /sdcard/DeepSeekHarness/tmp/y.xml "$env:USERPROFILE\.dsh\scratch\y.xml"
$xml2 = [System.IO.File]::ReadAllText("$env:USERPROFILE\.dsh\scratch\y.xml")
$m2 = [regex]::Matches($xml2, 'text="(执行|取消)"[^>]*bounds="\[(\d+),(\d+)\]\[(\d+),(\d+)\]"')
foreach($x in $m2){
  if($x.Groups[1].Value -eq '执行'){
    $cx=([int]$x.Groups[2].Value+[int]$x.Groups[4].Value)/2
    $cy=([int]$x.Groups[3].Value+[int]$x.Groups[5].Value)/2
    & adb -s $S shell "input tap $cx $cy"
  }
}
```

### 步骤 8：重启手机端引擎

**改的是 `lib/index.js`（宿主侧）→ 必须重启。**
只改 `lib/client.js`（前端）→ 刷新页面即可，不用重启。

重启方式二选一：

**A. 点主控台的「重启」按钮**（推荐，引擎在跑时用这个）

**B. 命令行**
```powershell
& adb -s $S shell "am force-stop com.deepseek.harness"
Start-Sleep -Seconds 3
& adb -s $S shell "am start -n com.deepseek.harness/.MainActivity"
Start-Sleep -Seconds 45   # 等引擎起来
```

#### 🔴 force-stop 之后 **App 不会自动起引擎**（2026-10-23 踩到）

走 B 那条路，App 打开后主控台显示的是**「未启动」**，`3080` 和 `3098` 一个都不在监听。
我傻等 100 秒才发现 —— 不是崩溃，是**根本没点「启动引擎」**。

**正确顺序：**

```powershell
& adb -s $S shell "am force-stop com.deepseek.harness"
Start-Sleep -Seconds 3
& adb -s $S shell "am start -n com.deepseek.harness/.MainActivity"
Start-Sleep -Seconds 5
# ⚠️ 必须手动点「启动引擎」按钮（截图定位，约 (310, 1240)）
& adb -s $S shell "input tap 310 1240"
# 然后轮询端口，别盲等
```

**判据：轮询 `netstat`，别用固定 sleep。**
实测点了「启动引擎」后 **约 25 秒**两个端口才起来。

```powershell
foreach ($i in 1..24) {
  $ports = & adb -s $S shell "netstat -tln 2>/dev/null | grep -E ':3080|:3098'" 2>&1 | Out-String
  if (($ports -match ':3080') -and ($ports -match ':3098')) { "✅ 起来了（+$($i*5)s）"; break }
  Start-Sleep -Seconds 5
}
```

**怎么区分「没启动」和「白页」**：看主控台截图。
- 显示「未启动」+ 蓝色「启动引擎」按钮 = **没启动**，点它就行
- 显示「运行中」但界面一片白 = **白页**，是 client.js 挂了

`/api/state` 返回 200 **不代表代码更新了** —— 旧代码也返回 200。

"syncing      = " + ($o.PSObject.Properties.Name -contains 'syncing')      # 2026-10-23 加的

`cp` 报成功、文件大小对了，但引擎还在跑旧代码的情况是存在的（没重启）。

## 四、设备选择（必读）

**同一个手机 USB + 无线同时连着时，adb 会报：**

```
adb.exe: more than one device/emulator
```

**先看有哪些：**

```powershell
& adb devices -l
```

输出长这样（同一个手机，两种连接）：

```
10AE5P278U000RZ                              device product:PD2366 ...
adb-10AE5P278U000RZ-w6VG2F (3)._adb-tls-connect._tcp  device product:PD2366 ...
```

**两条路：**

1. **加 `-s` 指定**（推荐，稳定）
   ```powershell
   & adb -s 10AE5P278U000RZ shell "..."
   ```
   USB 序列号是纯字母数字那个（`10AE5P278U000RZ`）。

2. **断开一条**
   ```powershell
   & adb disconnect   # 断无线
   ```

⚠️ **每次写命令都带 `-s`**，否则新会话照着抄会全报错。

#### 🔴 只插无线时，`-s 10AE5P278U000RZ` **会报 device not found**（2026-10-23 踩到）

`10AE5P278U000RZ` 是 **USB** 序列号。没插 USB、只开无线调试时，设备名是完整的：

```
adb-10AE5P278U000RZ-w6VG2F._adb-tls-connect._tcp
```

**`-s 10AE5P278U000RZ` 会报 `device '10AE5P278U000RZ' not found`。**

**正确做法：从 `adb devices -l` 里原样复制第一列。**

```powershell
# 先看实际名字
& adb devices -l
# 再原样用（含 ._adb-tls-connect._tcp 后缀）
$S = "adb-10AE5P278U000RZ-w6VG2F._adb-tls-connect._tcp"
```

**为什么容易错**：无线调试的端口号每次重连都会变（我这次见过 `44977` / `40931` / `41811`），
但 **mDNS 服务名里的那个 `w6VG2F` 是固定的**，所以完整名可以硬编码复用。

**别做的事**：不要 `adb connect 192.168.1.11:5555` —— 那是老式无线调试的端口，
新版「无线调试」不走 5555，会报 `积极拒绝`。让 `adb mdns services` 自己发现。

```powershell
& adb mdns services     # 看有哪些 _adb-tls-connect._tcp 服务
& adb devices -l        # 已连上的会列出来，直接用第一列
```

## 五、踩过的坑（改代码前先看一遍）

### 坑 1：中文进 shell 脚本 → 乱码

App 身份执行时，脚本里的中文会变成 `???`。

**规矩：推给手机的 `.sh` 一律纯 ASCII。**
用 `Out-File -Encoding ASCII`，脚本里只用英文和符号。

> 实证：`# fish-sync: 大肥鱼 <-> 小肥鱼` 写进 patch 后变成
> `# fish-sync: ??? <-> ???`。功能没坏，但以后看到的人会以为文件坏了。

### 坑 2：PowerShell 写 JSON 带 BOM → curl 解析失败

```powershell
# ❌ 错的（带 BOM）
"{\"code\":\"ABC\"}" | Out-File x.json -Encoding UTF8

# ✅ 对的（无 BOM）
$utf8NoBom = New-Object System.Text.UTF8Encoding($false)
[System.IO.File]::WriteAllText($path, $json, $utf8NoBom)
```

**症状**：`curl --data-binary @x.json` 后，服务端说「请填配对码」——
因为 JSON 开头有个不可见字符 `\uFEFF`，`JSON.parse` 直接失败。

**判据**：本地文件字节数比预期多 3 就对了（BOM 是 3 字节）。

### 坑 3：盲点坐标 → 点到通知/别的 App

`uiautomator dump` 拿到的坐标是**当前界面**的。
如果中途来了通知（heads-up 弹窗），它会盖在上面，你点下去就点进通知了。

**规矩：**
1. 每次点之前先 dump
2. dump 完先确认「我在哪个界面」（找特征文字，比如 `DEEPSEEK HARNESS`）
3. 不在预期界面就**停手**，别猜

> 实证：2026-10-22 点了两次都点进邮件通知，主人以为我在乱点他的手机。

### 坑 4：`process.exit()` 触发 libuv 断言

CLI 用 `process.exit()` 硬退，fetch 连接还开着：

```
Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)
```

**修法**：改 `process.exitCode`，让事件循环自己收尾。
或者给请求加 `connection: close`。

### 坑 5：`Copy-Item` 的 `-Destination` 静默失败

路径含中文/特殊字符时，命令返回空、文件没更新，但**不报错**。

**规矩：用 `-LiteralPath`。**

### 坑 6：改前端 vs 改宿主，生效方式不同

| 改了什么 | 怎么生效 |
|:---|:---|
| `lib/client.js`（浏览器侧） | 刷新页面就行，**不用重启** |
| `lib/index.js` / `server.js` 等（宿主侧） | **必须重启 DSH** |
| `cordis.patch.yml` 的 `config` 段 | 热生效（`patchReload: live`） |
| `package.json` 的 `dsh.bundle` | **必须重启** |

⚠️ **最容易误判的一条**：`patchReload: live` 只热重载**配置**，不重载**代码**。
我把 `DEFAULT_TARGETS`（代码里的常量）当成配置改了，以为热生效，结果 403。

## 六、配对状态在哪

```
电脑：C:\Users\you\.dsh\fish-sync\paired.json
手机：/data/user/0/com.deepseek.harness/files/payload/dshhome/fish-sync/paired.json
```

里面是 `secret`（长期密钥）和 `peer`（对端地址）。

**删掉这个文件 = 解除配对。** 删完重新输一次 6 位码就成。
